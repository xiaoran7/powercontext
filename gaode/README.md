## 二、核心技术与执行流程（四步法）

### 2.1 高德 MCP Server 工具能力映射

Skill 引导 Agent 精准调用高德开放平台 MCP Server 核心能力：

1. **地理编码（`maps_geo`）**：将自然语言地标（如“杭州西湖文化广场地铁站”）解析为标准坐标 `经度,纬度`；
2. **周边搜索（`maps_around_search`）**：传入起点经纬度、业态关键词（如咖啡馆、餐厅、公园）与搜索半径（默认 1200~1500 米），召回候选地点；
3. **关键字搜索（`maps_text_search`）**：在缺少精确坐标时按城市及关键词检索商户；
4. **步行路线规划（`maps_direction_walking`）**：输入起点与各候选终点坐标，获取真实的 `distance`（米）与 `duration`（秒），**严禁用直线距离或估算代替**。

### 2.2 四步推荐工作流

```
用户自然语言需求（起点 + 类型 + 时间限制 + 排序偏好）
       │
       ▼
【步骤 1：需求解析与约束提取】
  - 提取起点坐标/名称、目标类型、步行上限（如 <= 15 分钟）、数量上限（默认 <= 3 家）、排序偏好（近一点）
  - 标记需声明“未核实”的软性要求（安静程度、排队情况、营业状态等）
       │
       ▼
【步骤 2：调用高德工具查询周边候选地点】
  - 调用 maps_around_search（或 maps_text_search）拉取周边真实 POI 列表
  - 类型核验：剔除写字楼、停车场等无关干扰项
       │
       ▼
【步骤 3：逐一调用高德步行路线规划工具核验距离与耗时】
  - 逐个调用 maps_direction_walking(origin=起点, destination=候选点)
  - 读取真实 distance（米）与 duration（秒，折算分钟）
  - 严守红线：各地点独立规划（不串多站），绝不使用直线距离替代
       │
       ▼
【步骤 4：条件过滤、偏好排序与生成推荐】
  - 硬性条件过滤：剔除所有步行耗时 > T 分钟（如 > 900 秒）的候选
  - 偏好排序：按真实步行耗时/距离由近及远升序排序
  - 截取推荐：截取前 K 个（K <= 3）并输出结构化总览表格与详情卡片
```

## 三、异常与鲁棒性准则（四大防线）

1. **真实性铁律（零幻觉）**：地点名称、详细地址、经纬度、步行距离（米）、步行时间（分钟/秒）100% 取自高德 MCP 工具返回，严禁自行编造。
2. **信息缺失“未核实”标注**：对高德未返回的软性属性（安静程度、排队情况、营业状态、Wi-Fi 等），显式标注为“未核实”，严禁主观编造。
3. **符合条件结果不足（宁缺毋滥）**：只有 1~2 家满足步行限制时，只推荐满足条件的地点，绝不拿超时地点凑数，并说明原因。
4. **零结果与服务异常友好兜底**：无满足条件地点或高德服务异常时，如实说明情况并建议放宽步行时间或扩大搜索范围，绝不假造结果。
